## Most useful takeaways

- When a production symptom crosses domains, give the coding agent observations rather than a guessed solution. Here the important evidence is that opponents always appear to be AI snapshots while leaderboard ELO still moves.
- Separate investigation from mutation. “Do not open a PR yet; report what you think is happening” creates a review point before an uncertain diagnosis can alter production code.
- Treat public free-form text as hostile input even when it is “just feedback.” Authenticate, length-limit, rate-limit, sanitize, moderate links/profanity, and explicitly defend the downstream model against prompt injection.
- Build the feedback pipeline in stages: collect safely, triage, reproduce, file a durable issue, then later authorize automated implementation. Each boundary is independently observable and reversible.
- User feedback becomes far more actionable when agents classify it and chart recurring themes. Their first pass immediately exposes mobile layout and matchmaking as systemic problems rather than isolated comments.
- Prioritize correctness, stability, reliability, and the core loop before adding roadmap features. The live categorization says roughly 71% of feedback is bugs, making that tradeoff measurable rather than philosophical.
- Play unusual strategies, not only the happy path. Spending all available gold exposes a progression dead-end that ordinary scripted play had missed.
- For launch metadata, inspect the actual Open Graph tags and test the deployed URL in a preview tool; a favicon or image existing in the repository does not prove platforms will render it.
- Full autopilot is safer when responsibilities are split: one bot triages, another reproduces, a coding bot fixes, a verifier checks the work, and a play-test bot exercises the product. Independent evidence matters more than agent confidence.
- Reproduction is a gate, not ceremony. If an agent cannot make the reported problem happen, it probably lacks enough context to be trusted with the fix.

## Condensed narrative

The first half begins with launch metrics and a suspicious matchmaking/ELO inconsistency, then turns into one of Day 3's most practical workflows. The team creates a public feedback route but treats it as an adversarial boundary, layering authentication, rate limits, sanitization, moderation, and prompt-injection defenses. They route the resulting Slack stream through an agent factory that classifies reports, reproduces bugs with a play-test agent, and files confirmed issues in Notion. Live categorization makes mobile layout, matchmaking, and stability the immediate priorities. They then extend the factory toward production autopilot, but add the crucial controls: reproduce before fixing, rigorously verify every change, and use an independent agent to validate the triage and implementation.
