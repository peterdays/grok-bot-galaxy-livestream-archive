## Most useful takeaways

- Delay code inspection until there is behavioral evidence, but do not replace code review with screenshots. Reproduction, automated tests, preview interaction, security review, and source review catch different classes of failure.
- A project-manager bot is useful when it maintains a real external state surface: task, owner, status, dependency, evidence, and the exact human decision blocking progress.
- Preserve raw prompts and agent responses for audit and learning, but do not treat them as a ready-made reusable studio. Distill durable principles, tests, architecture, and decision records; remove secrets and irrelevant conversational noise.
- High-quality voice bug reports are structurally identical to written ones: identify the exact user/entity, compare observed values across surfaces, state expected consistency, and request investigation plus verification.
- A call transcript improves traceability, but the resulting agent task and PR still need stable identifiers so the spoken request can be connected to code, tests, deployment, and outcome.
- The cheater bot is the clearest adversarial product test in the block. If ordinary browser automation can farm a human ladder, rank, rewards, sponsorship, and paid visibility are not trustworthy.
- Voice-agent “hang up if prompting gets weird” is not a complete guardrail. Use tool allowlists, schema validation, authentication, rate limits, content moderation, confirmation for consequential actions, and separate untrusted caller text from instructions.
- A feedback factory should never auto-merge solely because it reproduced a report. Apply risk tiers, independent tests, protected branches, canaries, rollback, and human review where user data or money is involved.
- Durable project chats help coordinate parallel agents, but long context needs explicit summaries, source links, task state, and regression tests. Claims of thousands of chats over months are not validated in this demo.
- Human review before social posting is a good boundary because mistakes become immediately public and can impersonate the account owner.
- “Merged” and “live soon” are not acceptance criteria. The paid-leaderboard feature is merged, then cannot be found; deployment status and an end-to-end user path should be verified before declaring success.
- Monetizing rankings or prompts magnifies abuse, moderation, disclosure, refund, and platform-integrity obligations. Those policies must precede the payment surface.
