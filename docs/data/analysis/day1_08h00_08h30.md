## Most useful takeaways

- Start fleet design from an inventory of actual recurring work, then group related tasks under a specialist. A chief-of-staff front door is optional: it reduces interface complexity but also hides details from operators who prefer direct control.
- Do not mistake a prompt for a hard policy boundary. The presenter's “cosplay determinism” phrase is accurate: asking a model to consult deterministic code is useful, but a serious control must be enforced outside the model so it cannot bypass the check.
- Centralize integrations so multiple agents can reference one maintained source of truth. Imported sessions/cookies can reduce repeated login friction, but they also enlarge the security blast radius and must be isolated and revocable.
- If an API is unavailable, headless DOM automation is usually cheaper and faster than screenshot/vision loops. It still remains more fragile than a supported API.
- Multi-agent group chat is not free coordination. Proactive workers can all respond to one another, multiplying token spend and noise; direct, temporary handoffs are often better.
- Memory pruning can be explicit. If a worker keeps anchoring on irrelevant history, tell it what to forget rather than discarding all of its accumulated role knowledge.
- Separate local and remote work by constraints. Cloud execution preserves the user's machine and supports parallelism; local execution is useful for local-only apps but can steal focus and resources.
- The clean coding orchestration boundary is: the persistent manager chooses and packages relevant context, the specialized cloud coding agent edits the repository, and the manager independently tests the returned change in the real environment.
- Before assigning research, ask a domain expert what variables actually determine success. The venue search becomes materially better only after permit, service, kitchen, vendor, time, and capacity constraints are made explicit.

## Safety caveats

- A model calling deterministic code is not equivalent to a policy enforcement point. Put authorization, budgets, approval gates, and allow/deny rules in the surrounding system.
- Shared files, imported cookies, password-manager access, and local execution are privileged capabilities. Use least-privilege accounts, separate profiles, logs, expiration, and revocation.
- Respect service terms and bot restrictions; an agent being technically capable of navigating a site does not grant permission to automate it.
