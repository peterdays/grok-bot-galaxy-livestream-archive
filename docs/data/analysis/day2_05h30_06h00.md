## Most useful takeaways

- Generate an evidence-backed work journal automatically from commits, PRs, messages, documents, and published output. Daily facts can roll into weekly summaries, stand-ups, reviews, and a persistent knowledge base.
- Prefer a reusable code representation when assets must stay synchronized. A React/Remotion animation can reuse the same components, colors, and layout rules as the product and render into multiple platform formats.
- Install a mature tool-specific skill before asking a general coding agent to use an unfamiliar framework. Existing constraints and examples improve first-pass behavior and reduce rediscovery.
- Inspect what the agent actually generated—changed files, dependency wiring, server output, and browser console—rather than judging only the rendered surface.
- An agent caused the demo's broken wiring and another debugging pass repaired it. Generated volume (roughly 6,000 lines here) is not evidence of correctness.
- A disposable single-file prototype can validate the interaction quickly, then be converted into a structured client while the authoritative backend is implemented separately.
- Use precise element-level feedback for visual iteration: remove a specific decoration, tighten a specific stack, simplify particular cards. This closes the design loop faster than rewriting a large prompt.
- When a domain is difficult for models to manipulate directly, expose it through code or another structured, testable interface. That often improves capability, token efficiency, versioning, and reuse.
