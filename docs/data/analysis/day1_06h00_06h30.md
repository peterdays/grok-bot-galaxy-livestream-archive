## Most useful takeaways

- Judge agents by completed results, not conversational output. They should return for approval at explicit decision points rather than continuously ask what to do next.
- An “attention list” can compare what a PM actually spent time on with the declared priority list—a practical chief-of-staff use case rather than generic summarization.
- The engineering-manager agent is deliberately instructed not to code. It decomposes work, delegates to several engineering agents, and runs verification loops over their output.
- Specialized roles help both the human and the model: humans know where to route work, while each bot accumulates a smaller, cleaner body of task-relevant memory.
- Data access can remove the delay between a product question and a tested query/chart. Scheduled queries also turn dashboards into pushed morning or hourly launch reports.
- The most instructive moment is a failure caught early: the presenters infer that seat selection is the largest leak, but their data bot points out that the actual drop is from search to fare selection. Agentic speed makes this validation step more—not less—important.
- Their PRD skill favors short-lived, implementation-oriented documents with crisp P0/P1/P2 requirements. The document is a bridge from evidence to code, not a permanent artifact.
- Even with a context-rich agent, humans are expected to review the proposal, add judgment, and iterate through comments in the source document.
- A recorded UI demonstration can become a reusable operational skill, which is particularly useful for complex CRM and back-office workflows that are awkward to describe in prose.
- A design system gives the implementation manager reusable constraints; the manager can then decompose one approved design into small, independently verifiable coding tasks.
- Verification effort should scale with risk. Cheap visual or deterministic checks can run everywhere, while expensive end-to-end review is reserved for high-impact changes.
- Manager prompts should define ownership, decomposition, supervision, and proof—not micromanage each coding step.
- Suppress successful no-op routine notifications. Human attention should be reserved for decisions, failures, and meaningful state changes.

## Condensed narrative

The PM workshop begins by defining useful agent colleagues and showing a role-shaped fleet. Its most important live example is a correction loop: the humans misread a conversion funnel, the data specialist produces contrary evidence, and that evidence becomes a prioritized product spec. The approved design is then decomposed by an engineering manager across cloud coding agents, with verification effort scaled to risk and routine status noise suppressed.
