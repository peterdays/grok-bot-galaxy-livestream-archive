## Most useful takeaways

- Organize specialists around durable deliverables and interfaces: research evidence, positioning brief, landing-page specification, ad configuration, performance analysis, and orchestration.
- A cross-agent handoff should pass an artifact and its provenance, not merely a summary. Here, the research output feeds a Google Doc that the human can inspect, comment on, and send back for revision.
- Preserve a review surface between strategy and external execution. Google Docs comments and the campaign spreadsheet make assumptions, copy variants, and hypotheses visible before code or ads consume them.
- Run independent work in parallel only after declaring ownership. The product marketer edits the brief, performance marketer builds the shell, and web bot writes the landing page without competing for the same artifact.
- Do not confuse a campaign shell with a launched campaign. The demo deliberately stops before spend/payment approval and analyzes a previously run experiment instead.
- Analytics agents should return definitions, sample windows, spend, CTR/CVR, uncertainty, and raw-source links alongside recommendations. A declared “winner” without these checks can simply automate a bad conclusion.
- The highest-value orchestration pattern is learned from an observed human workflow: record where the human routes context, comments, approves, or corrects; only then ask a coordinator to take over the mechanical handoffs.
- The coordinator demo proves that work can be queued, not that three campaigns completed correctly. Completion, spend limits, asset review, and rollback still need independent evidence.
- A production URL is a concrete proof point, but it is not full verification. Test responsive layout, links, tracking, accessibility, and message fidelity on the deployed page before directing paid traffic to it.
- Avoid the speaker's broad “give it Slack/email and study everything” default. Start with least-privilege channels, folders, scopes, time ranges, redaction rules, and a defined purpose; expand access only when required.
- A shareable bot template can preserve valuable operating knowledge, but it also creates a supply-chain artifact. Strip secrets and customer data, version it, disclose permissions/connectors, and test it in a clean workspace.

## Condensed narrative

This is a substantive end-to-end marketing workflow demo. A market-research bot browses the mock airline site and competitors; a product-marketing bot receives that context, writes a Google Doc, incorporates live human comments, and produces landing-page and search-ad variants. In parallel, a performance bot builds a Google Ads shell and a repo-connected web bot turns the approved outline into a production landing page. The presenter correctly stops before launching the new paid campaign because budget and payment approval are missing, then uses a prior experiment to demonstrate analysis. Finally, he asks a project-manager bot to learn the observed handoffs and become the sole contact for three future campaigns. The page deployment is verified on air, but the queued campaigns are not. The wrap-up's suggestion to expose all Slack and email history should be replaced with a least-privilege onboarding policy.
