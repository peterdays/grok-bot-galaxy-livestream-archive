## Most useful takeaways

- Test the deployed interface at the target viewport. The team finds both a missing-information regression and controls hidden behind a ticker while exercising the real mobile layout.
- A good visual bug report states the observed behavior and user impact, then requires the agent to run the app and reproduce it before changing code. Screenshots and exact URLs reduce ambiguity further.
- Separate changes into independently reviewable jobs. Ability rendering, share cards, form placement, and responsive layout do not need to share one agent or one oversized PR.
- Keep working while agents run, but maintain visible ownership and status. The coordinator can fan work out; humans still inspect drafts, reject weak presentation, and decide when to merge.
- Verification means interacting with the changed product, not just reading code or passing unit tests. Browser runs, screenshots, preview deployments, and repeated play are the evidence used here.
- Turn the verification procedure into a reusable product skill. Teach the agent how to start the app, reach important states, perform core actions, and recognize success once; version that procedure as the UI evolves.
- Route every feedback channel into the same governed intake path, but preserve source, identity, consent, and trust level. Voice submissions should not bypass the validation and moderation applied to typed feedback.
- Never assume a cropped or partially masked credential is safe. If any token is shown during a stream, rotate or revoke it—not merely delete it from the UI—and review logs for use. The broadcast confirms deletion but does not demonstrate rotation.
- “Automatic merge after reproduction” still needs risk tiers. Cosmetic changes may be eligible; authentication, billing, data mutations, security controls, and schema changes require stronger review and rollback policy.
- Observability should alter priorities. Vercel shows more mobile than desktop traffic, making responsive defects more urgent; the data agent is updated to include that new source in recurring analysis.
- Sanity-check analytics and history against lived experience. When a displayed past match conflicts with a participant's memory, the team treats the data as suspect instead of confidently building on it.
- Cloud agents need reproducible development environments with least-privilege preview credentials, deterministic startup instructions, and isolation from production secrets.
