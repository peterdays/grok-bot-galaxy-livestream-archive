## Most useful takeaways

- A pivot can be evidence of progress. Overnight research and a domain expert revealed that the event idea had too many external dependencies, regulatory risks, and uninteresting-to-watch execution steps for the time box.
- Choose a project that exposes the skills you intend to demonstrate. The game creates visible product, design, coding, balance, infrastructure, and distribution work that can be completed and inspected during the stream.
- Separate deterministic identity from generated flavor. A template should mint the same core character/stats, while randomized rarity or visuals can add novelty without making the underlying mapping unstable.
- Constrain the total stat pool before asking an LLM to distribute it. The model can interpret a bot's description, but the fixed budget prevents it from creating arbitrary total power.
- Avoid monetization that changes competitive power. Cosmetics and optional presentation/arena features preserve the game loop better than paid stat advantages.
- The minimal vertical loop is explicit and testable: import a template, form a team, set a lineup, run one matchup, and show the result/replay. Everything else is an extension.
- The first glimpse of the engineering plan is promising: plan verification and type/function boundaries before delegating code, rather than starting from screens alone.
