## Most useful takeaways

- Supervision should be front-loaded. Early in a codebase, watch for recurring mistakes and shape the architecture; once conventions, tests, and verification are mature, move toward outcome-level review.
- A deliberately ugly prototype can expose both implementation bugs and product flaws quickly. Here it reveals bad stat totals, a broken slider, and later the absence of meaningful lineup strategy.
- Build a simulation/debug surface alongside the user-facing loop. Live constants, repeated match simulation, and transparent intermediate scores let both humans and agents verify game logic without guessing from animation.
- Resolve the game result independently of presentation. The deterministic match can finish instantly; animation/replay is a later visualization of that result. This separation simplifies testing and lets visuals evolve independently.
- Visual alternatives are product probes, not commitments. A second prototype reveals useful concepts—binder, ordering, matchup card, replay ID—that can be merged without preserving its implementation.
- When an agent applies a style too broadly, diagnose the prompt and representation problem rather than merely saying “less.” The shimmer also exposes a concrete responsive-scaling issue.
- Inspecting reasoning is most valuable when it changes the system. If an agent skipped code inspection or used a bad heuristic, encode the corrected method in an existing skill so the whole class of errors becomes less likely.
- Playing the MVP uncovers what planning missed: if stronger cards are always better and order is arbitrary, the game lacks interesting decisions. Health persistence, situational arenas, and matchup modifiers are proposed as ways to give weak cards strategic value.
